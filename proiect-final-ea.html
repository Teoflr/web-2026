Proiect Final: Aplicație CRUD cu integrare Google API (Calendar / Contacte)

Obiectivul Proiectului

Dezvoltarea unei aplicații web complete (portofoliu personal + instrument de gestiune) care se conectează la un serviciu Google la alegere – Calendar API sau People API (Contacte). Aplicația trebuie să permită utilizatorului autentificat să vizualizeze, adauge, editeze și șteargă intrări (evenimente sau persoane de contact) folosind API-ul real, oferind o experiență modernă de tip Single Page Application (SPA).

Proiectul îmbină o pagină de profil / CV cu o zonă funcțională de administrare a datelor, având cerințe clare de filtrare, sortare, paginare și gestionare a erorilor.

Cerințe Obligatorii (nota 5 – 7)

  1. Arhitectură și conținut personal (Portofoliu + Gestiune)
    • Secțiune Profil: Pagina trebuie să conțină numele studentului, rol/tehnologii preferate, o scurtă descriere și o fotografie de profil.
    • Secțiune centrală de administrare: O zonă dedicată unde sunt listate dinamic intrările (evenimente sau contacte) preluate de la Google API. Interfața trebuie să includă butoane clare pentru adăugare, editare și ștergere.
    • Experiență profesională (dacă există): joburi relevante în IT sau alte domenii, cu rol, companie și perioadă.
    • Educație: instituție, program de studii, perioadă (ex: „Facultatea de Informatică, UAIC – 2022‑2026”).
    • Design original şi personalizat – culori, tipografie, layout unic, care reflectă personalitatea studentului.
  2. Integrare Google API (Calendar SAU People API)
    • Autentificare OAuth 2.0 cu Google Identity Services. Studentul trebuie să solicite permisiunile necesare:
      • Pentru Calendar API: domeniu https://www.googleapis.com/auth/calendar.events (acces complet la evenimente).
      • Pentru People API: domeniu https://www.googleapis.com/auth/contacts (acces la contacte).
    • Efectuarea de requesturi asincrone (fetch + token OAuth) către endpoint-urile Google pentru a prelua lista de intrări existente.
    • Afișarea a cel puțin 5 intrări (evenimente sau contacte) sub formă de carduri sau tabel. Dacă utilizatorul are mai puține date reale, aplicația va afișa un mesaj sugestiv și va oferi posibilitatea de a adăuga date demonstrative (mock local sau localStorage).
  3. Operații CRUD complete (Create, Read, Update, Delete)
    • Adăugare (Create): Formular dedicat pentru crearea unei noi intrări.
      Calendar: titlu, dată început, dată sfârșit, locație (opțional).
      Contacte: nume, prenume, email, telefon, companie.
    • Citire (Read): Afișarea corectă a proprietăților relevante din răspunsul API.
    • Editare (Update): Fiecare intrare are buton „Editează” – se deschide un formular precompletat, iar modificările sunt trimise la API (PATCH/PUT).
    • Ștergere (Delete): Buton „Șterge” cu confirmare înainte de a trimite cererea de ștergere.
    • După fiecare operație CRUD, lista de intrări se reîmprospătează dinamic fără reîncărcarea paginii.
  4. Design responsiv

    Layout-ul trebuie să se adapteze pe telefon, tabletă și desktop folosind CSS Grid / Flexbox sau framework-uri moderne (Bootstrap, Tailwind).

Cerințe Medii (nota 8 – 9)

  1. Filtrare și sortare pe client‑side
    • Implementarea unei bare de căutare care filtrează intrările în timp real (după titlu/eveniment sau după nume/email contact).
    • Filtrare suplimentară: pentru Calendar – filtrare după interval de date (ex: evenimente din ultimele 7 zile); pentru Contacte – filtrare după inițiala numelui sau după domeniul de email.
    • Sortare: evenimente după dată (crescător/descrescător), contacte alfabetic după nume.
  2. Experiență utilizator (UX) profesională
    • Stare de încărcare (loading): Prezentarea unui spinner sau skeleton în timpul cererilor către Google API (autentificare, preluare date, salvare, ștergere).
    • Gestionare erori completă: Dacă token-ul OAuth expiră, utilizatorul primește un mesaj prietenos și un buton de reautentificare. Dacă cererea eșuează (lipsă internet, rată limită, eroare API), UI-ul afișează un mesaj clar: „⚠️ Nu s‑au putut încărca datele. Verifică conexiunea sau încearcă din nou.” Aplicația nu trebuie să se oprească din funcționare.
    • Confirmare înainte de ștergere: un dialog modal sau confirm() personalizat pentru a preveni ștergerile accidentale.

Cerințe Avansate / Bonus (minim 1 subpunct pentru nota 10)

  1. Backend proxy securizat (Serverless / Node.js)
    • Pentru a ascunde cheile și token-urile, studentul va implementa un mini-server (Express în Node.js, funcții serverless pe Vercel/Netlify, sau PHP) care face schimbul OAuth și stochează token-ul de acces în variabile de mediu. Frontend-ul comunică doar cu acest proxy, iar proxy-ul adaugă antetul de autorizare către Google API. Token-ul NU este expus în browser.
  2. Paginare sau „Load More”

    Dacă utilizatorul are mai mult de 6 intrări (evenimente sau contacte), se va implementa un sistem de paginare (cu numere de pagină) sau un buton „Încarcă mai multe”, pentru a optimiza performanța și UX-ul.

  3. Deploy live + README profesionist
    • Proiectul trebuie să fie funcțional și accesibil public pe o platformă gratuită (Vercel, Netlify, Render, GitHub Pages – doar pentru frontend, dar pentru backend se poate folosi Vercel Serverless).
    • Repository-ul trebuie să conțină un fișier README.md detaliat: descriere, tehnologii utilizate, instrucțiuni de configurare (creare proiect în Google Cloud Console, activarea API-ului, variabile de mediu), capturi de ecran și link către aplicația live.
  4. Suport offline (PWA) – extra

    Service Worker + IndexedDB pentru a permite vizualizarea ultimelor date sincronizate chiar și fără conexiune. Modificările sunt salvate automat când conexiunea revine.

Recomandări tehnice și resurse

  • Autentificare Google: folosiți Google Identity Services for Web (GIS) sau biblioteca gapi. Pentru vanilla JS, implementați fluxul OAuth 2.0 implicit cu redirecționare.
  • Endpoint-uri relevante:
    • Calendar API: GET https://www.googleapis.com/calendar/v3/calendars/primary/events (listă evenimente)
      POST https://www.googleapis.com/calendar/v3/calendars/primary/events (creare)
      PATCH / PUT / DELETE pe URL-ul specific evenimentului.
    • People API (Contacte): GET https://people.googleapis.com/v1/people/me/connections?personFields=names,emailAddresses,phoneNumbers,organizations
      POST https://people.googleapis.com/v1/people:createContact
      PATCH https://people.googleapis.com/v1/{resourceName}:updateContact
      DELETE https://people.googleapis.com/v1/{resourceName}
  • Paginare la API-ul Google: folosiți parametrii maxResults și pageToken pentru a itera prin rezultate. Implementarea paginării în frontend trebuie să fie intuitivă.
  • Stocare stare: În versiunea fără backend, token-ul OAuth poate fi păstrat în memorie sau în sessionStorage, dar atenție la securitate. Backend-ul proxy este recomandat pentru nota maximă.

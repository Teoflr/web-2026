Material UI

Build accessible React interfaces with components, themes, responsive layouts, and feedback patterns.

Time: 3–4 hours Level: Intermediate Before you begin: Complete React Hooks & Routing Current stack: Material UI 9.6.0, React 19.3.1, Vite 8.3.8
On this page Introduction Installation Setup Components Theming Layout Advanced Project

What is Material UI?

1

A component library for React

Material UI, usually shortened to MUI, is a React component library based on Material Design. It supplies tested interface building blocks while leaving application data and behavior under your control.

Components
Buttons, fields, cards, dialogs, tables, navigation, and many other accessible interface patterns.
Design system
A shared approach to color, typography, spacing, shape, elevation, and responsive breakpoints.
Customization
The sx prop handles local styles, while a theme defines application-wide design decisions.
Accessibility
Components include keyboard and focus behavior, but you must still provide labels, useful text, and a logical document structure.
MUI reduces repeated interface work; it does not replace React. State, events, data fetching, routing, and application structure still use the React concepts from the previous tutorials.

Install Material UI

2

Create a Vite React project

Start with the same Vite setup used in the React tutorials. Vite 8 requires Node.js 20.19+ or 22.12+; use an active LTS release for course work.

# Create a React project npm create vite@latest my-mui-app -- --template react # Enter the project and install its dependencies cd my-mui-app npm install
Run the remaining commands inside my-mui-app. If node --version reports an older version, update Node.js before continuing.
3

Install the component packages

The core package uses Emotion as its default styling engine. Icons and the Roboto font are separate packages so applications only install them when needed.

# Core components and styling engine npm install @mui/material @emotion/react @emotion/styled # Icons and the default Material Design typeface npm install @mui/icons-material @fontsource/roboto
  • @mui/material: Core components and theme utilities.
  • @emotion/react and @emotion/styled: The default CSS-in-JS engine.
  • @mui/icons-material: Material Symbols packaged as React SVG components.
  • @fontsource/roboto: Local font files that are bundled by Vite.
Do not install @mui/lab unless a project uses one of its experimental components. None of the examples in this tutorial require it.
4

Load the font and baseline styles

Import the font weights you use in src/main.jsx. CssBaseline applies a small cross-browser reset and theme-aware page defaults.

import { StrictMode } from 'react' import { createRoot } from 'react-dom/client' import { CssBaseline } from '@mui/material' import '@fontsource/roboto/300.css' import '@fontsource/roboto/400.css' import '@fontsource/roboto/500.css' import '@fontsource/roboto/700.css' import App from './App.jsx' createRoot(document.getElementById('root')).render( <StrictMode> <CssBaseline /> <App /> </StrictMode>, )

The icon package renders SVGs, so it does not need a Material Icons font link in index.html.

First component

5

Build the first MUI screen

Replace the starter contents of src/App.jsx. Import each component by name and use sx for styles that belong to this one instance.

import { Button, Container, Typography } from '@mui/material' function App() { return ( <Container maxWidth="sm" sx={{ py: 4 }}> <Typography variant="h2" component="h1" gutterBottom > Welcome to Material UI </Typography> <Typography variant="body1" sx={{ mb: 2 }}> This screen uses responsive spacing and theme typography. </Typography> <Button variant="contained" size="large"> Get started </Button> </Container> ) } export default App
npm run dev
Open the local address printed by Vite. The heading, spacing, button, ripple, focus state, and Roboto typeface should now be visible.

Essential components

6

Buttons and actions

Choose a button variant according to the action's importance. Most views should have one clear primary action.

import { Button, Stack } from '@mui/material' import { Delete, Send } from '@mui/icons-material' function ButtonShowcase() { return ( <Stack direction={{ xs: 'column', sm: 'row' }} spacing={2} > <Button variant="contained" startIcon={<Send />}> Send message </Button> <Button variant="outlined"> Cancel </Button> <Button variant="text" color="error" startIcon={<Delete />}> Delete </Button> </Stack> ) }
  • Contained: The highest-emphasis action, such as Save or Submit.
  • Outlined: A secondary action, such as Cancel or Back.
  • Text: A low-emphasis action within a card, dialog, or toolbar.
7

Controlled text fields

A MUI input is controlled in the same way as a native React input: state supplies the value and an event handler updates it.

import { useState } from 'react' import { Stack, TextField } from '@mui/material' function AccountFields() { const [email, setEmail] = useState('') const [password, setPassword] = useState('') const passwordIsShort = password.length > 0 && password.length < 8 return ( <Stack spacing={3} sx={{ maxWidth: 420 }}> <TextField label="Email address" type="email" value={email} onChange={(event) => setEmail(event.target.value)} helperText="We will not share your email" required /> <TextField label="Password" type="password" value={password} onChange={(event) => setPassword(event.target.value)} error={passwordIsShort} helperText={passwordIsShort ? 'Use at least 8 characters' : 'Enter a password'} required /> </Stack> ) }

The visible label is also the field's accessible name. Do not use a placeholder as the only label.

8

Cards for related content

Cards group one subject and its actions. Keep action labels specific and write meaningful alternative text for content images.

import { Button, Card, CardActions, CardContent, CardMedia, Typography, } from '@mui/material' import { FavoriteBorder, Share } from '@mui/icons-material' function AnimalCard() { return ( <Card sx={{ maxWidth: 345 }}> <CardMedia component="img" height="200" image="https://mui.com/static/images/cards/contemplative-reptile.jpg" alt="Green lizard resting on a branch" /> <CardContent> <Typography gutterBottom variant="h5" component="h2"> Lizard </Typography> <Typography variant="body2" color="text.secondary"> Lizards are a widespread group of squamate reptiles. </Typography> </CardContent> <CardActions> <Button size="small" startIcon={<FavoriteBorder />}>Like</Button> <Button size="small" startIcon={<Share />}>Share</Button> </CardActions> </Card> ) }

Custom theming

9

Create an application theme

A theme centralizes design choices. Wrap the application once, near the root, so every MUI component can read the same values.

import { CssBaseline } from '@mui/material' import { createTheme, ThemeProvider } from '@mui/material/styles' const theme = createTheme({ palette: { primary: { main: '#5e35b1' }, secondary: { main: '#00897b' }, }, typography: { fontFamily: '"Roboto", "Helvetica", "Arial", sans-serif', h1: { fontSize: '2.5rem', fontWeight: 700 }, button: { textTransform: 'none' }, }, shape: { borderRadius: 10 }, }) function Root() { return ( <ThemeProvider theme={theme}> <CssBaseline /> <App /> </ThemeProvider> ) }
Use the theme for repeated design decisions. Keep one-off layout adjustments close to the component with sx.
10

Add light and dark color schemes

The current color-scheme API stores the user's choice and applies the correct palette. A component that calls useColorScheme must be inside the matching ThemeProvider.

import { Button, CssBaseline, Stack, Typography } from '@mui/material' import { createTheme, ThemeProvider, useColorScheme, } from '@mui/material/styles' const theme = createTheme({ colorSchemes: { light: true, dark: true, }, }) function ColorModeControl() { const { mode, setMode } = useColorScheme() if (!mode) { return <Button disabled>Loading color mode</Button> } return ( <Stack direction="row" spacing={2} alignItems="center"> <Typography>Mode: {mode}</Typography> <Button variant="outlined" onClick={() => setMode(mode === 'dark' ? 'light' : 'dark')} > Toggle mode </Button> </Stack> ) } function App() { return ( <ThemeProvider theme={theme}> <CssBaseline /> <ColorModeControl /> </ThemeProvider> ) }
Do not read the initial mode during server rendering without accounting for hydration. MUI may return undefined on the first render, which is why this example includes a loading state.
11

Recognize older MUI examples

Search results and older tutorials can use APIs that have since changed. Prefer the current documentation when the patterns conflict.

  • Current Grid items use size={{ xs: 12, md: 6 }}; older examples use item xs={12} md={6}.
  • Clickable list rows use ListItemButton; older examples use <ListItem button>.
  • Actions at the end of a list row use the secondaryAction prop; older examples use ListItemSecondaryAction.
  • Use onKeyDown, because React deprecated onKeyPress.
  • Prefer sx over deprecated system props and repeated inline style objects.

Responsive layout

12

Build a responsive Grid

MUI breakpoints are mobile-first. Each value applies at that breakpoint and remains active until a larger breakpoint overrides it.

import { Card, CardContent, Grid, Typography } from '@mui/material' const cards = ['Components', 'Themes', 'Layouts'] function ResponsiveCards() { return ( <Grid container spacing={3}> {cards.map((title) => ( <Grid key={title} size={{ xs: 12, md: 6, lg: 4 }}> <Card sx={{ height: '100%' }}> <CardContent> <Typography variant="h5" component="h2"> {title} </Typography> </CardContent> </Card> </Grid> ))} </Grid> ) }
  • xs: 0px and wider.
  • sm: 600px and wider.
  • md: 900px and wider.
  • lg: 1200px and wider.
  • xl: 1536px and wider.
13

Combine AppBar and responsive Drawers

Use a temporary Drawer on small screens and a permanent Drawer from sm upwards. This keeps the menu available without covering desktop content.

import { useState } from 'react' import { AppBar, Box, Drawer, IconButton, List, ListItemButton, ListItemIcon, ListItemText, Toolbar, Typography, } from '@mui/material' import { Home, Menu, Person, Settings } from '@mui/icons-material' const drawerWidth = 240 const destinations = [ { label: 'Home', icon: <Home /> }, { label: 'Profile', icon: <Person /> }, { label: 'Settings', icon: <Settings /> }, ] function AppLayout() { const [mobileOpen, setMobileOpen] = useState(false) const drawer = ( <> <Toolbar /> <List> {destinations.map(({ label, icon }) => ( <ListItemButton key={label}> <ListItemIcon>{icon}</ListItemIcon> <ListItemText primary={label} /> </ListItemButton> ))} </List> </> ) return ( <Box sx={{ display: 'flex' }}> <AppBar position="fixed" sx={{ zIndex: (theme) => theme.zIndex.drawer + 1 }} > <Toolbar> <IconButton color="inherit" edge="start" aria-label="Open navigation" onClicksetMobileOpen(true)} sx={{ mr: 2, display: { sm: 'none' } }} > <Menu /> </IconButton> <Typography variant="h6" component="h1">Dashboard</Typography> </Toolbar> </AppBar> <Box component="nav" aria-label="Main navigation"> <Drawer variant="temporary" open={mobileOpen} onClosesetMobileOpen(false)} ModalProps={{ keepMounted: true }} sx={{ display: { xs: 'block', sm: 'none' }, '& .MuiDrawer-paper': { width: drawerWidth } }} > {drawer} </Drawer> <Drawer variant="permanent" open sx={{ display: { xs: 'none', sm: 'block' }, '& .MuiDrawer-paper': { width: drawerWidth } }} > {drawer} </Drawer> </Box> <Box component="main" sx={{ flexGrow: 1, p: 3, width: { sm: `calc(100% - ${drawerWidth}px)` } }} > <Toolbar /> <Typography variant="h4">Main content</Typography> </Box> </Box> ) }

Advanced components

14

Sortable and selectable tables

Keep sort and selection state in React. Copy the source array before sorting so the module-level data is not mutated.

import { useState } from 'react' import { Checkbox, Paper, Table, TableBody, TableCell, TableContainer, TableHead, TableRow, TableSortLabel, } from '@mui/material' const people = [ { id: 1, name: 'John Doe', email: 'john@example.com', role: 'Admin' }, { id: 2, name: 'Jane Smith', email: 'jane@example.com', role: 'User' }, { id: 3, name: 'Bob Johnson', email: 'bob@example.com', role: 'Editor' }, ] function PeopleTable() { const [order, setOrder] = useState('asc') const [orderBy, setOrderBy] = useState('name') const [selected, setSelected] = useState([]) function handleSort(property) { const isAscending = orderBy === property && order === 'asc' setOrder(isAscending ? 'desc' : 'asc') setOrderBy(property) } function toggleSelected(id) { setSelected((current) => current.includes(id) ? current.filter((selectedId) => selectedId !== id) : [...current, id], ) } const sortedPeople = [...people].sort((a, b) => { const comparison = a[orderBy].localeCompare(b[orderBy]) return order === 'asc' ? comparison : -comparison }) const allSelected = selected.length === people.length return ( <TableContainer component={Paper}> <Table aria-label="People"> <TableHead> <TableRow> <TableCell padding="checkbox"> <Checkbox checked={allSelected} indeterminate={selected.length > 0 && !allSelected} onChangesetSelected(allSelected ? [] : people.map((person) => person.id))} slotProps={{ input: { 'aria-label': 'Select all people' } }} /> </TableCell> <TableCell> <TableSortLabel active={orderBy === 'name'} direction={orderBy === 'name' ? order : 'asc'} onClickhandleSort('name')} > Name </TableSortLabel> </TableCell> <TableCell>Email</TableCell> <TableCell>Role</TableCell> </TableRow> </TableHead> <TableBody> {sortedPeople.map((person) => ( <TableRow key={person.id} hover selected={selected.includes(person.id)}> <TableCell padding="checkbox"> <Checkbox checked={selected.includes(person.id)} onChangetoggleSelected(person.id)} slotProps={{ input: { 'aria-label': `Select ${person.name}` } }} /> </TableCell> <TableCell>{person.name}</TableCell> <TableCell>{person.email}</TableCell> <TableCell>{person.role}</TableCell> </TableRow> ))} </TableBody> </Table> </TableContainer> ) }
15

Dialogs and snackbars

Dialogs ask the user to complete a focused task. Snackbars provide brief, non-blocking feedback after an action.

import { useState } from 'react' import { Alert, Button, Dialog, DialogActions, DialogContent, DialogTitle, Snackbar, TextField, } from '@mui/material' function AddPerson() { const [dialogOpen, setDialogOpen] = useState(false) const [saved, setSaved] = useState(false) const [name, setName] = useState('') function handleSubmit(event) { event.preventDefault() setDialogOpen(false) setSaved(true) setName('') } return ( <> <Button variant="contained" onClicksetDialogOpen(true)}> Add person </Button> <Dialog open={dialogOpen} onClosesetDialogOpen(false)}> <DialogTitle>Add a person</DialogTitle> <DialogContent component="form" id="add-person-form" onSubmit={handleSubmit}> <TextField autoFocus fullWidth required margin="dense" label="Full name" value={name} onChange={(event) => setName(event.target.value)} /> </DialogContent> <DialogActions> <Button onClicksetDialogOpen(false)}>Cancel</Button> <Button type="submit" form="add-person-form" variant="contained">Save</Button> </DialogActions> </Dialog> <Snackbar open={saved} autoHideDuration={4000} onClosesetSaved(false)}> <Alert severity="success" variant="filled" onClosesetSaved(false)}> Person saved </Alert> </Snackbar> </> ) }

Complete project

16

Build a task manager

This example combines state, forms, lists, icons, chips, layout, and theme-aware styling.

import { useState } from 'react' import { Button, Card, CardContent, Chip, Container, IconButton, List, ListItem, ListItemText, Stack, TextField, Typography, } from '@mui/material' import { Add, CheckCircle, Delete } from '@mui/icons-material' const initialTasks = [ { id: 1, title: 'Learn Material UI', completed: false, priority: 'high' }, { id: 2, title: 'Build a React app', completed: true, priority: 'medium' }, ] function TaskManager() { const [tasks, setTasks] = useState(initialTasks) const [newTask, setNewTask] = useState('') function addTask() { const title = newTask.trim() if (!title) return setTasks((current) => [ ...current, { id: crypto.randomUUID(), title, completed: false, priority: 'medium' }, ]) setNewTask('') } function toggleTask(id) { setTasks((current) => current.map((task) => task.id === id ? { ...task, completed: !task.completed } : task, ), ) } function deleteTask(id) { setTasks((current) => current.filter((task) => task.id !== id)) } return ( <Container maxWidth="md" sx={{ py: 4 }}> <Typography variant="h3" component="h1" gutterBottom> Task manager </Typography> <Card sx={{ mb: 3 }}> <CardContent> <Stack direction={{ xs: 'column', sm: 'row' }} spacing={2}> <TextField fullWidth label="New task" value={newTask} onChange={(event) => setNewTask(event.target.value)} onKeyDown={(event) => { if (event.key === 'Enter') addTask() }} /> <Button variant="contained" startIcon={<Add />} onClick={addTask}> Add </Button> </Stack> </CardContent> </Card> <Card> <List aria-label="Tasks"> {tasks.map((task) => ( <ListItem key={task.id} divider secondaryAction={ <Stack direction="row"> <IconButton onClicktoggleTask(task.id)} color={task.completed ? 'success' : 'default'} aria-label={task.completed ? `Mark ${task.title} incomplete` : `Complete ${task.title}`} > <CheckCircle /> </IconButton> <IconButton onClickdeleteTask(task.id)} color="error" aria-label={`Delete ${task.title}`}> <Delete /> </IconButton> </Stack> } > <ListItemText primary={task.title} slotProps={{ primary: { sx: { textDecoration: task.completed ? 'line-through' : 'none', opacity: task.completed ? 0.6 : 1, }, }, }} secondary={<Chip label={task.priority} size="small" color={task.priority === 'high' ? 'error' : 'warning'} />} /> </ListItem> ))} </List> {tasks.length === 0 && ( <Typography color="text.secondary" sx={{ p: 3, textAlign: 'center' }}> No tasks yet. Add one above. </Typography> )} </Card> </Container> ) }
The project now supports adding, completing, and deleting tasks; responsive input layout; accessible icon labels; priority chips; and theme-aware colors.
17

Where to go next

You now have the core patterns needed to build a consistent MUI application. Extend the task manager before adding more libraries:

  • Persist tasks with the custom local-storage Hook from the previous tutorial.
  • Add filtering and editing while keeping state updates immutable.
  • Move repeated component overrides into the theme.
  • Add routes for the dashboard, tasks, and settings screens.
  • Test interactions with Vitest and React Testing Library.
  • Explore MUI X only when the project needs advanced data grids or date pickers.

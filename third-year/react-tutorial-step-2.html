React Hooks

1

What Hooks are

Class and function components

Hooks were introduced in React 16.8. They let function components use React features such as state, context, refs, and effects. Class components remain supported, but function components and Hooks are the normal choice for new React code.

// Class component pattern class Counter extends React.Component { constructor(props) { super(props); this.state = { count: 0 }; } render() { return ( <div> <p>Count: {this.state.count}</p> <button onClick={() => this.setState({count: this.state.count + 1})}> Increment </button> </div> ); } } // Function component with Hooks function Counter() { const [count, setCount] = useState(0); return ( <div> <p>Count: {count}</p> <button onClick={() => setCount(count + 1)}> Increment </button> </div> ); }
Terminology:
• Component: A reusable function or class that describes part of the interface
• Hook: A function whose name starts with use and connects a component to a React feature
• Custom Hook: A function that combines Hooks to share stateful logic, not shared state itself

Each component render is a snapshot. Hooks let React retain state between those renders and synchronize the component with systems outside React. Hooks do not automatically make an application faster; their main benefit is composition.

Hook Rules:
• Call Hooks at the top level, not inside loops, conditions, event handlers, or nested functions
• Call Hooks only from React function components or custom Hooks
• Name custom Hooks with a use prefix
• Keep eslint-plugin-react-hooks enabled; it checks these rules and effect dependencies

Why Hooks matter

  • Local state: A component can remember values between renders
  • Synchronization: Effects can connect to browser APIs, networks, and subscriptions
  • Reusable logic: Custom Hooks can package related state and effects
  • Composition: Small components and Hooks can be combined without inheritance

useState in depth

3

useState recap and update patterns

useState gives a component a value that persists between renders. It returns the current state and a setter. Calling the setter queues another render with the new value; it does not change the state variable in the currently running render.

Use separate state variables for independent values. Group values when they are normally updated together, and use a reducer when transitions become difficult to describe with several setters.

Basic useState Pattern:

import { useState } from 'react' function BasicCounter() { // Declare state variable with initial value const [count, setCount] = useState(0) return ( <div> <p>Count: {count}</p> <button onClick={() => setCount(count + 1)}> Increment </button> </div> ) }
4

Functional Updates - Avoiding Stale Closures

When the next state depends on the previous state, pass an updater function. React applies queued updater functions in order. Passing a value directly is appropriate when the next value does not depend on the old one.

Render snapshots: An event handler sees the state from the render that created it. Multiple calls such as setCount(count + 1) therefore queue the same value. Updater functions receive the latest queued state.
import { useState } from 'react' function SafeCounter() { const [count, setCount] = useState(0) // Direct update: uses the value captured by this render const incrementBad = () => { setCount(count + 1) // Uses current closure value } // Updater function: receives the latest queued state const incrementGood = () => { setCount(prevCount => prevCount + 1) // Function gets latest state } // Update by a supplied amount const incrementByAmount = (amount) => { setCount(prevCount => prevCount + amount) } // Conditional update const incrementIfEven = () => { setCount(prevCount => prevCount % 2 === 0 ? prevCount + 1 : prevCount ) } return ( <div> <p>Count: {count}</p> <button onClick={incrementGood}>Safe Increment</button> <button onClick={() => incrementByAmount(5)}>+5</button> <button onClick={incrementIfEven}>Increment if Even</button> </div> ) }

Complex State Objects

Managing complex state objects requires careful consideration of immutability.

import { useState } from 'react' function UserProfile() { // Complex state object const [user, setUser] = useState({ name: '', email: '', age: 0, preferences: { theme: 'light', notifications: true, language: 'en' }, hobbies: [] }) // Update one property without mutating the object const updateName = (newName) => { setUser(prevUser => ({ ...prevUser, name: newName })) } // Copy each level that changes const updateTheme = (newTheme) => { setUser(prevUser => ({ ...prevUser, preferences: { ...prevUser.preferences, theme: newTheme } })) } // Add to an array by creating a new array const addHobby = (hobby) => { setUser(prevUser => ({ ...prevUser, hobbies: [...prevUser.hobbies, hobby] })) } // Remove from an array with filter const removeHobby = (hobbyIndex) => { setUser(prevUser => ({ ...prevUser, hobbies: prevUser.hobbies.filter((_, index) => index !== hobbyIndex) })) } return ( <div> <h3>User Profile</h3> <input type="text" placeholder="Name" value={user.name} onChange={(e) => updateName(e.target.value)} /> <select value={user.preferences.theme} onChange={(e) => updateTheme(e.target.value)}> <option value="light">Light</option> <option value="dark">Dark</option> </select> <div> <h4>Hobbies:</h4> {user.hobbies.map((hobby, index) => ( <div key={index}> {hobby} <button onClick={() => removeHobby(index)}>Remove</button> </div> ))} <button onClick={() => addHobby('Reading')}>Add Reading</button> </div> <pre>{JSON.stringify(user, null, 2)}</pre> </div> ) }

useEffect and external systems

6

What an Effect does

useEffect synchronizes a component with a system outside React: a network connection, timer, browser API, third-party widget, or subscription. If a value can be calculated from props or state during render, it normally should not be stored or updated in an Effect.

An Effect has three parts:
• Setup connects to or updates the external system
• Dependencies list every reactive value used by setup
• Optional cleanup undoes the previous setup before a rerun or unmount
7

Basic useEffect Patterns

import { useState, useEffect } from 'react' function EffectExamples() { const [count, setCount] = useState(0) // 1. No dependency array: run after every committed render useEffect(() => { console.log('Component rendered') }) // 2. Empty array: reconnect only when the component mounts useEffect(() => { console.log('Component connected') }, []) // 3. Effect with dependencies - runs when dependencies change useEffect(() => { console.log(`Count changed to: ${count}`) // Update document title document.title = `Count: ${count}` }, [count]) // 4. Effect with cleanup function useEffect(() => { const timer = setInterval(() => { console.log('Timer tick') }, 1000) // Cleanup runs before the next setup and when the component unmounts return () => { clearInterval(timer) console.log('Timer cleaned up') } }, []) return ( <div> <p>Count: {count}</p> <button onClick={() => setCount(c => c + 1)}>Increment</button> </div> ) }

How the dependency list works

The dependency list is the array passed as the second argument to useEffect. It tells React which reactive values the Effect reads. A reactive value is a prop, state value, or variable or function created inside the component. Include every reactive value used by the setup and cleanup functions.

After each committed render, React compares every dependency with its value from the previous render using Object.is. If at least one value is different, React first runs the previous cleanup and then runs the new setup with values from the latest render.

// No dependency list: run after every committed render useEffect(() => { synchronize() }) // Empty list: this Effect has no reactive dependencies useEffect(() => { connectOncePerMount() return () => disconnect() }, []) // Dependency list: rerun when roomId or serverUrl changes useEffect(() => { const connection = createConnection(serverUrl, roomId) connection.connect() return () => connection.disconnect() }, [serverUrl, roomId])
What normally belongs in the list:
• Props read by the Effect
• State values read by the Effect
• Variables and functions declared in the component and read by the Effect

What normally does not belong in the list:
• State setter functions, because React keeps their identity stable
• Constants declared outside the component, because rendering cannot change them
• ref.current, because changing it does not trigger a render; the ref object itself is stable

The dependency list is a description of the code, not a scheduling preference. Do not remove a dependency merely to stop an Effect from rerunning. That makes the Effect use an older render's value, which is called a stale closure. Keep the React Hooks lint rule enabled and change the Effect's structure when the linter reports a missing dependency.

Objects and functions as dependencies

Objects and functions created during rendering receive a new identity on every render. If one is a dependency, the Effect can rerun even when its contents appear unchanged. When possible, create that object or function inside the Effect, or depend on the primitive values used to build it. Use useMemo or useCallback only when stable identity is required elsewhere as well.

const serverUrl = 'https://chat.example.com' function ChatRoom({ roomId }) { useEffect(() => { // Create the object inside the Effect so it is not a dependency const options = { serverUrl, roomId } const connection = createConnection(options) connection.connect() return () => connection.disconnect() }, [roomId]) // serverUrl is declared outside the component }
Development behavior: With StrictMode, React may run an Effect's setup, cleanup, and setup again during development. This checks whether cleanup fully reverses setup. Production does not perform that extra development check.
8

Data Fetching with useEffect

A small client-only component can fetch data in an Effect. Use cleanup so an obsolete request cannot update current state. For route data, React Router loaders or a framework data API usually provide better caching, loading, error, and server-rendering behavior.

import { useState, useEffect } from 'react' function UserList() { const [users, setUsers] = useState([]) const [loading, setLoading] = useState(true) const [error, setError] = useState(null) useEffect(() => { const controller = new AbortController() const fetchUsers = async () => { try { setLoading(true) setError(null) const response = await fetch( 'https://jsonplaceholder.typicode.com/users', { signal: controller.signal } ) if (!response.ok) { throw new Error('Failed to fetch users') } const userData = await response.json() setUsers(userData) } catch (err) { if (err.name !== 'AbortError') { setError(err.message) } } finally { if (!controller.signal.aborted) { setLoading(false) } } } fetchUsers() return () => controller.abort() }, []) if (loading) return <div>Loading users...</div> if (error) return <div>Error: {error}</div> return ( <div> <h3>Users ({users.length})</h3> <ul> {users.map(user => ( <li key={user.id}> {user.name} - {user.email} </li> ))} </ul> </div> ) }
9

Debounce an external request

This Effect waits until typing pauses before starting a request. Its cleanup cancels the pending timeout when the query changes.

import { useState, useEffect } from 'react' function SearchComponent() { const [query, setQuery] = useState('') const [results, setResults] = useState([]) const [isSearching, setIsSearching] = useState(false) // Debounced search effect useEffect(() => { if (!query.trim()) { setResults([]) return } const timeoutId = setTimeout(async () => { setIsSearching(true) try { // Simulate API call const response = await fetch( `https://jsonplaceholder.typicode.com/posts?q=${query}` ) const data = await response.json() setResults(data.slice(0, 5)) // Limit results } catch (error) { console.error('Search failed:', error) setResults([]) } finally { setIsSearching(false) } }, 500) // 500ms debounce // Cleanup: cancel the timeout if query changes return () => clearTimeout(timeoutId) }, [query]) return ( <div> <h3>Search Posts</h3> <input type="text" value={query} onChange={(e) => setQuery(e.target.value)} placeholder="Search posts..." /> {isSearching && <p>Searching...</p>} <ul> {results.map(post => ( <li key={post.id}>{post.title}</li> ))} </ul> </div> ) }

Context and shared values

10

What Context does

Context distributes a value to descendants without passing it through every intermediate component. It is a dependency-delivery mechanism, not a complete state-management system. State still lives in a component, reducer, or external store.

When to Use Context:
• Values needed throughout one part of the tree, such as authentication, theme, or locale
• Avoiding prop drilling through multiple levels
• Stable configuration that many descendants need

A consumer rerenders when its nearest provider receives a different value. Keep providers close to the area that needs them and avoid putting unrelated, frequently changing values in one context.
11

Creating and Using Context

This example creates a theme context and a custom Hook that verifies the provider is present. React 19 allows the context object itself to be rendered as a provider. The older <ThemeContext.Provider> form remains compatible.

// ThemeContext.jsx import { createContext, useContext, useState } from 'react' // 1. Create the context const ThemeContext = createContext() // 2. Create a custom hook for using the context export const useTheme = () => { const context = useContext(ThemeContext) if (!context) { throw new Error('useTheme must be used within a ThemeProvider') } return context } // 3. Create the provider component export const ThemeProvider = ({ children }) => { const [theme, setTheme] = useState('light') const [primaryColor, setPrimaryColor] = useState('#333333') // Theme configuration const themes = { light: { background: '#ffffff', text: '#000000', border: '#cccccc' }, dark: { background: '#1a1a1a', text: '#ffffff', border: '#444444' } } const toggleTheme = () => { setTheme(prev => prev === 'light' ? 'dark' : 'light') } const value = { theme, setTheme, primaryColor, setPrimaryColor, toggleTheme, colors: themes[theme] } return ( <ThemeContext value={value}> {children} </ThemeContext> ) }
12

Using Context in Components

Any descendant can read the nearest provider value through useTheme. Components outside that provider receive the default value passed to createContext; this example throws instead so a missing provider is caught early.

// Components that use the theme context import { useTheme } from './ThemeContext' // Header component using theme const Header = () => { const { colors, toggleTheme, theme } = useTheme() const headerStyle = { backgroundColor: colors.background, color: colors.text, borderBottom: `1px solid ${colors.border}`, padding: '1rem', display: 'flex', justifyContent: 'space-between', alignItems: 'center' } return ( <header style={headerStyle}> <h1>My App</h1> <button onClick={toggleTheme}> Switch to {theme === 'light' ? 'dark' : 'light'} mode </button> </header> ) } // Card component using theme const Card = ({ title, content }) => { const { colors, primaryColor } = useTheme() const cardStyle = { backgroundColor: colors.background, color: colors.text, border: `1px solid ${colors.border}`, borderRadius: '8px', padding: '1rem', margin: '1rem 0', borderLeft: `4px solid ${primaryColor}` } return ( <div style={cardStyle}> <h3>{title}</h3> <p>{content}</p> </div> ) } // Settings component const Settings = () => { const { primaryColor, setPrimaryColor, colors } = useTheme() const colors_list = ['#111111', '#333333', '#666666', '#999999'] return ( <div style={{ backgroundColor: colors.background, color: colors.text, padding: '1rem' }}> <h3>Settings</h3> <div> <label>Primary Color: </label> <select value={primaryColor} onChange={(e) => setPrimaryColor(e.target.value)}> {colors_list.map(color => ( <option key={color} value={color}>{color}</option> ))} </select> </div> </div> ) }
13

Complete App with Context

The provider owns the shared state. Components below it can consume the value, while components outside it remain unaffected.

// App.jsx - Main application component import { ThemeProvider } from './ThemeContext' function App() { return ( <ThemeProvider> <div className="app"> <Header /> <main style={{ padding: '1rem' }}> <Card title="Welcome" content="This is a React Context theme example." /> <Card title="Features" content="Toggle between light and dark themes, and change the primary color." /> <Settings /> </main> </div> </ThemeProvider> ) } export default App

Custom Hooks

14

Custom Hook: useLocalStorage

A custom Hook is a JavaScript function that starts with use and calls other Hooks. It shares behavior, not one global state value: every component call receives its own state unless the Hook connects to a shared external store. This example persists state in localStorage and listens for updates from other tabs.

// useLocalStorage.jsx - Custom hook import { useState, useEffect } from 'react' export function useLocalStorage(key, initialValue) { // Get value from localStorage or use initialValue const [storedValue, setStoredValue] = useState(() => { try { const item = window.localStorage.getItem(key) return item ? JSON.parse(item) : initialValue } catch (error) { console.error(`Error reading localStorage key "${key}":`, error) return initialValue } }) // Preserve the useState setter API, including updater functions const setValue = (value) => { setStoredValue(previous => typeof value === 'function' ? value(previous) : value ) } // Synchronize local state to the external browser API useEffect(() => { try { window.localStorage.setItem(key, JSON.stringify(storedValue)) } catch (error) { console.error(`Error setting localStorage key "${key}":`, error) } }, [key, storedValue]) // Listen for changes made by other tabs useEffect(() => { const handleStorageChange = (e) => { if (e.key === key && e.newValue !== null) { setStoredValue(JSON.parse(e.newValue)) } } window.addEventListener('storage', handleStorageChange) return () => { window.removeEventListener('storage', handleStorageChange) } }, [key]) return [storedValue, setValue] } // Example usage component function PersistentCounter() { const [count, setCount] = useLocalStorage('counter', 0) const [name, setName] = useLocalStorage('username', '') return ( <div> <h3>Persistent Counter</h3> <input type="text" placeholder="Enter your name" value={name} onChange={(e) => setName(e.target.value)} /> <p>Hello {name || 'Anonymous'}. Count: {count}</p> <button onClick={() => setCount(c => c + 1)}> Increment </button> <button onClick={() => setCount(0)}> Reset </button> <p style={{ fontSize: '0.8em', color: 'gray' }}> This data persists after a page refresh. </p> </div> ) }

useMemo

15

Cache an expensive calculation

What is Memoization?
Memoization stores a calculated value and reuses it while its inputs remain unchanged. The cache is an optimization, not a semantic guarantee; your component must still work if React recalculates the value.

useMemo is useful when a measured calculation is expensive or when a stable object or array identity is required by another optimization. Do not add it to every calculation. It has its own bookkeeping cost and can make dependencies harder to maintain.

React Compiler can automatically memoize many values and functions when a project enables it. Manual memoization remains useful for specific identity requirements and performance work confirmed with the React DevTools Profiler.

Basic Syntax

const memoizedValue = useMemo(() => { // Expensive calculation return computeExpensiveValue(a, b); }, [a, b]); // Only recalculates when a or b changes

Practical Example: Expensive List Filtering

import { useState, useMemo } from 'react'; function ExpensiveList() { // Generate a large dataset const [items, setItems] = useState(() => Array.from({ length: 10000 }, (_, i) => ({ id: i, name: `Item ${i}`, category: i % 3 === 0 ? 'A' : i % 3 === 1 ? 'B' : 'C', price: Math.random() * 100 })) ); const [filter, setFilter] = useState(''); const [category, setCategory] = useState('all'); const [minPrice, setMinPrice] = useState(0); // Recalculate only when one of these inputs changes const { filteredItems, stats } = useMemo(() => { console.log('Filtering 10,000 items'); const filtered = items.filter(item => { const matchesName = item.name.toLowerCase().includes(filter.toLowerCase()); const matchesCategory = category === 'all' || item.category === category; const matchesPrice = item.price >= minPrice; return matchesName && matchesCategory && matchesPrice; }); // Calculate expensive statistics const stats = { total: filtered.length, avgPrice: filtered.length > 0 ? filtered.reduce((sum, item) => sum + item.price, 0) / filtered.length : 0, categories: filtered.reduce((acc, item) => { acc[item.category] = (acc[item.category] || 0) + 1; return acc; }, {}) }; return { filteredItems: filtered, stats }; }, [items, filter, category, minPrice]); // Only recalculate when these change return ( <div> <h4>Expensive List (10,000 items)</h4> <div style={{ display: 'flex', gap: '1rem', marginBottom: '1rem' }}> <input type="text" placeholder="Filter by name..." value={filter} onChange={(e) => setFilter(e.target.value)} /> <select value={category} onChange={(e) => setCategory(e.target.value)}> <option value="all">All Categories</option> <option value="A">Category A</option> <option value="B">Category B</option> <option value="C">Category C</option> </select> <input type="range" min="0" max="100" value={minPrice} onChange={(e) => setMinPrice(Number(e.target.value))} /> <span>Min Price: ${minPrice.toFixed(0)}</span> </div> <div style={{ marginBottom: '1rem', padding: '1rem', background: '#f5f5f5' }}> <h5>Statistics</h5> <p>Total Items: {stats.total}</p> <p>Average Price: ${stats.avgPrice.toFixed(2)}</p> <p>Categories: {Object.entries(stats.categories).map(([cat, count]) => `${cat}: ${count}`).join(', ')}</p> </div> <ul> {filteredItems.slice(0, 20).map(item => ( <li key={item.id}> {item.name} - {item.category} - ${item.price.toFixed(2)} </li> ))} {filteredItems.length > 20 && ( <li>... and {filteredItems.length - 20} more items</li> )} </ul> </div> ); }
When to use useMemo:
• Expensive calculations (complex filtering, sorting, mathematical operations)
• Preserving object or array identity for a memoized consumer
• Computing derived state from multiple variables

When NOT to use useMemo:
• Simple calculations (basic arithmetic, string concatenation)
• Every computation; memoization also has overhead
• Primitive values that don't need memoization

useCallback

16

Keep a function reference stable

useCallback keeps the same function reference until one of its dependencies changes. Creating a function during render is normal and usually cheap. Stable identity matters when a callback is passed to a component wrapped in memo, used as another Hook's dependency, or registered with an external system.

Basic Syntax

const memoizedCallback = useCallback(() => { // Function logic doSomething(a, b); }, [a, b]); // Only recreate if a or b changes

Without a stable callback

// A new function reference is created on each render function ParentWithoutCallback() { const [count, setCount] = useState(0); const [name, setName] = useState(''); // This is only a problem when a consumer relies on stable identity const handleClick = () => { console.log('Button clicked'); }; return ( <div> <p>Count: {count}</p> <input value={name} onChange={(e) => setName(e.target.value)} placeholder="Type something..." /> {/* ExpensiveChild re-renders every time parent renders */} <ExpensiveChild onClick={handleClick} /> <button onClick={() => setCount(count + 1)}> Increment Count </button> </div> ); } // Child component that should only re-render when its props actually change const ExpensiveChild = React.memo(({ onClick }) => { console.log('ExpensiveChild rendered'); // Logs on every parent render return ( <div style={{ padding: '1rem', border: '2px solid #666' }}> <h4>Expensive Child Component</h4> <button onClick={onClick}>Click Me</button> <p>This component does expensive calculations...</p> </div> ); });

Using useCallback where identity matters

// Keep the callback reference stable for the memoized child import React, { useState, useCallback } from 'react'; function ParentWithCallback() { const [count, setCount] = useState(0); const [name, setName] = useState(''); // This callback has no reactive dependencies const handleClick = useCallback(() => { console.log('Button clicked'); }, []); // Empty dependency array means function never changes // The updater form removes count from the dependencies const handleIncrement = useCallback(() => { setCount(prevCount => prevCount + 1); }, []); // No dependencies needed due to functional update // State setters have stable identity const handleReset = useCallback(() => { setCount(0); }, []); // No dependencies needed // This callback only uses its argument and a state setter const handleNameChange = useCallback((newName) => { setName(newName); console.log(`Name changed to: ${newName}`); }, []); // No dependencies needed for setter return ( <div> <p>Count: {count}</p> <p>Name: {name}</p> <input value={name} onChange={(e) => handleNameChange(e.target.value)} placeholder="Type something..." /> {/* ExpensiveChild only re-renders when handleClick actually changes */} <OptimizedChild onClick={handleClick} /> <button onClick={handleIncrement}> Increment Count </button> <button onClick={handleReset}> Reset Count </button> </div> ); } const OptimizedChild = React.memo(({ onClick }) => { console.log('OptimizedChild rendered'); // Logs when a prop changes return ( <div style={{ padding: '1rem', border: '2px solid #111' }}> <h4>Optimized Child Component</h4> <button onClick={onClick}>Click Me</button> <p>This component only rerenders when its prop changes.</p> </div> ); });
Use useCallback when:
• Passing functions to memoized child components
• Functions are dependencies of other hooks
• An external subscription requires a stable callback

Usually skip it when:
• Child components aren't memoized
• Profiling shows no relevant rendering cost
• Functions are only used within the same component
Performance Debugging Tip:
Use React DevTools Profiler before adding manual memoization. A component that renders frequently with unchanged props may be a candidate for memo and useCallback. React Compiler can automate many of these optimizations in projects that enable it.

Performance Optimization Tips

Important patterns to avoid unnecessary re-renders and optimize your React applications.

Common Performance Issues:
• Creating objects/functions in render
• Unnecessary re-renders due to reference changes

useReducer

18

Describe state transitions with a reducer

useReducer centralizes related state transitions in one function. A component dispatches an action that describes what happened, and the reducer returns the next state. Reducers must be pure: do not mutate existing state, perform network requests, read changing globals, or trigger other side effects inside them.

Basic Syntax

const [state, dispatch] = useReducer(reducer, initialState); // Reducer function signature function reducer(state, action) { switch (action.type) { case 'ACTION_TYPE': return { ...state, /* new state */ }; default: throw new Error(`Unknown action: ${action.type}`); } }

Example 1: Advanced Counter with History

import { useReducer } from 'react'; // Reducer function - pure function that returns new state function counterReducer(state, action) { switch (action.type) { case 'INCREMENT': return { count: state.count + (action.payload || 1), history: [...state.history, `+${action.payload || 1}`] }; case 'DECREMENT': return { count: state.count - (action.payload || 1), history: [...state.history, `-${action.payload || 1}`] }; case 'RESET': return { count: 0, history: [...state.history, 'RESET'] }; case 'UNDO': if (state.history.length === 0) return state; const newHistory = state.history.slice(0, -1); const lastAction = state.history[state.history.length - 1]; let newCount = state.count; if (lastAction === 'RESET') { // Complex undo logic could go here newCount = 0; // Simplified } else if (lastAction.startsWith('+')) { const amount = parseInt(lastAction.slice(1)); newCount = state.count - amount; } else if (lastAction.startsWith('-')) { const amount = parseInt(lastAction.slice(1)); newCount = state.count + amount; } return { count: newCount, history: newHistory }; default: throw new Error(`Unknown action type: ${action.type}`); } } function AdvancedCounter() { const [state, dispatch] = useReducer(counterReducer, { count: 0, history: [] }); return ( <div> <h4>Advanced Counter: {state.count}</h4> <div style={{ display: 'flex', gap: '0.5rem', marginBottom: '1rem' }}> <button onClick={() => dispatch({ type: 'INCREMENT' })}>+1</button> <button onClick={() => dispatch({ type: 'INCREMENT', payload: 5 })}>+5</button> <button onClick={() => dispatch({ type: 'DECREMENT' })}>-1</button> <button onClick={() => dispatch({ type: 'DECREMENT', payload: 5 })}>-5</button> <button onClick={() => dispatch({ type: 'RESET' })}>Reset</button> <button onClick={() => dispatch({ type: 'UNDO' })}>Undo</button> </div> <div> <h5>History:</h5> <p>{state.history.join(' → ') || 'No actions yet'}</p> </div> </div> ); }

Choosing between useReducer and useState:

Use useState when:
• Simple state updates (strings, numbers, booleans)
• Independent state variables
• Few state update functions

Use useReducer when:
• Complex state logic with multiple sub-values
• State transitions depend on previous state
• Many different actions/updates
• State is a complex object or array
• Named actions make transitions easier to test and understand

Routing concepts and installation

React Router maps URLs to interface elements and keeps navigation synchronized with browser history. Version 8 provides Declarative, Data, and Framework modes. This guide uses Declarative Mode because it is the smallest step from a Vite client application.

What is Client-Side Routing?
Client-side routing changes the URL and rendered route without requesting a complete HTML document for each navigation. The server must still be configured to return the app entry point for valid client routes. Data and Framework modes add loaders, actions, pending states, and other route-level features.

Why React Router?

  • Declarative Routing: Define routes using JSX components for clear, readable code
  • Dynamic Routing: URL segments can identify records such as /users/:id
  • Code Splitting: Works seamlessly with React.lazy() for route-based code splitting
  • History Management: Handles browser history, back/forward buttons, and URL synchronization
  • Route Data: Data and Framework modes can coordinate loading and mutations with navigation

Core Router Components

• Navigate: Hook for programmatic navigation
• Params: Dynamic segments in URLs (e.g., /users/:id)

Web Navigation Layout Options:
• Layout component: Shared navigation structure across routes
• Outlet: Where nested route content renders
• useLocation: Access current route for active link styling
• Link component: Declarative navigation with active states
• Nested routes: Organize routes hierarchically
• Route-specific layouts: Different layouts for different sections
• CSS-in-JS styling: Dynamic styles based on route state
• Responsive design: Layouts that adapt to screen sizes
• Search integration: URL-based search with query parameters
Best Practices for Web Navigation Layout:
• Keep navigation consistent across all pages
• Use visual indicators for active/current page
• Implement responsive design for mobile devices
• Use breadcrumbs for deep navigation hierarchies
• Follow web accessibility guidelines (ARIA labels, keyboard navigation)
• Consider SEO implications of your routing structure
• Test navigation on different screen sizes and devices
• Use semantic HTML for better accessibility

Review and next routing topics

The examples used React Router's Declarative Mode: a browser router, route elements, URL parameters, links, navigation Hooks, and nested layouts. This is enough for straightforward client-rendered applications.

Review:
  • BrowserRouter synchronizes the app with browser history.
  • Routes and Route map URL patterns to elements.
  • Link and NavLink handle accessible internal navigation.
  • useParams reads path segments; useSearchParams reads and updates the query string.
  • useNavigate is for navigation caused by application logic.
  • Nested routes and Outlet create shared layouts.
For route loaders, actions, pending UI, error boundaries, and server rendering, continue with React Router's Data or Framework Mode. These modes coordinate data with navigation more effectively than fetching route data in component Effects.

Apply the concepts to one feature before adding another abstraction. Profile first when working on performance, and choose route data APIs when data belongs to a URL.

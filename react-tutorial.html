What each tool does

The setup uses four related tools. They do different jobs:

React
A JavaScript library for building an interface from components. React code eventually runs in the browser.
Node.js
A runtime that executes JavaScript outside the browser. It runs Vite and the other development tools on your computer; it is not a web server you need to write for this lesson.
npm
The package manager installed with Node.js. It downloads packages, records exact versions, and runs commands defined by the project.
Vite
The development server and build tool. It serves the project locally, updates the browser after edits, and creates optimized files for deployment.

Create React App was deprecated in 2025. React recommends a framework for production applications, but Vite remains a good way to learn client-side React without introducing a framework first.

Vite 8 uses native modules during development and Rolldown for production builds. It updates the page as files change.

Install and scaffold

3

Install Node.js

Install Node.js once on your computer. npm is included in the same installation.

1. Choose an LTS release

  1. Open nodejs.org.
  2. Choose the download marked LTS, not Current. LTS releases receive longer support and are the safer default for a course or project.
  3. As of 26 October 2026, the LTS line is Node.js 24. Node.js 26 becomes LTS on 28 October. Either line can run this project.

2. Run the installer

  • Windows: Download the .msi installer, keep the default options, and allow it to add Node.js to PATH.
  • macOS: Download the .pkg installer for your Mac and keep the default options.
  • Linux: Use one of the package-manager or version-manager commands listed on the Node.js download page. Distribution repositories can contain an older release, so check the version after installation.

A version manager such as nvm or fnm is useful when several projects require different Node.js releases, but it is not required for this lesson.

3. Open a new terminal

Close any terminal that was open during installation, then open Terminal, PowerShell, or the terminal in your editor. A new session reloads the updated PATH.

4. Verify Node.js and npm

Run each command separately:

node --version npm --version
Both commands should print a version, for example v24.x.x for Node.js and 11.x.x for npm. The exact patch number can differ. Vite 8 requires Node.js 22.12 or newer; Node.js 20 is no longer supported.
If the terminal reports “command not found” or “not recognized,” open a new terminal first. If the error remains, run the installer again and make sure Node.js is added to PATH. Do not fix a normal local project by running npm with sudo.
4

Create the project

1. Choose the parent directory

The command will create a new folder named my-react-app. First, move the terminal to the directory that should contain that folder. For example:

# macOS or Linux cd ~/Documents # Windows PowerShell cd $HOME\Documents

Use another location if you prefer. The cd command changes the terminal's current directory.

2. Ask Vite to scaffold the app

npm create vite@latest my-react-app -- --template react

The parts of this command mean:

  • npm create runs a project generator.
  • vite@latest uses the latest stable create-vite package.
  • my-react-app is the new folder and package name. Use a lowercase name without spaces.
  • The first -- passes the remaining options to create-vite.
  • --template react selects React with JavaScript. Use react-ts only if the course uses TypeScript.

Choose Oxlint when asked which linter to use. When asked whether to install and start now, choose No so the next commands remain visible as separate steps.

To skip both prompts, run npm create vite@latest my-react-app -- --template react --no-interactive. Non-interactive mode selects Oxlint and does not install the dependencies automatically.

3. Enter the project directory

cd my-react-app

Commands from this point must run inside this folder. It contains package.json, the file that lists the project's packages and scripts.

4. Install the dependencies

npm install

npm reads package.json, downloads the required packages into node_modules/, and writes package-lock.json with the exact resolved versions. Do not edit node_modules/ by hand or commit it to source control.

5. Start the development server

npm run dev

npm run dev runs the dev script from package.json. Vite prints a local address, normally http://localhost:5173. Open it in a browser. Leave the terminal running while you work.

Save a source file to see the browser update. Press Ctrl+C in the terminal when you want to stop the server.

6. Know the other project commands

# Check the source with the configured linter npm run lint # Create an optimized production build in dist/ npm run build # Preview the production build locally npm run preview
When returning to the project later, open a terminal, run cd with the project's path, and then run npm run dev. Run npm install again only after dependencies change or when node_modules/ is missing.

The first React render

6

The entry point: main.jsx

A React project still begins with a normal HTML document. Vite loads src/main.jsx from a module script in index.html, and that JavaScript hands one part of the page over to React.

How the browser reaches React

  1. The browser requests index.html from the Vite development server.
  2. The HTML contains an empty <div id="root"></div>. This is the mounting point for the application.
  3. The module script loads src/main.jsx.
  4. main.jsx creates a React root and tells React to render <App /> inside the mounting point.
  5. App renders its child components, which render their own children. Together they form the component tree.

Open src/main.jsx. The current template contains:

import { StrictMode } from 'react' import { createRoot } from 'react-dom/client' import './index.css' import App from './App.jsx' createRoot(document.getElementById('root')).render( <StrictMode> <App /> </StrictMode>, )

Read the entry file

  • import makes code or CSS from another file available here. JavaScript modules let a project be split into focused files.
  • document.getElementById('root') finds the matching element in index.html.
  • createRoot(...) lets React manage the contents of that element.
  • render(<App />) starts the component tree with the root component.

StrictMode enables extra development checks. It may run some component logic twice in development to expose unsafe side effects; it does not do that in the production build. JSX no longer needs a default React import.

Most projects rarely change main.jsx. Day-to-day work happens in App.jsx and the components rendered below it.
7

The root component: App.jsx

App is a JavaScript function used as a React component. React calls it and uses the returned JSX as a description of what should appear on screen.

Replace src/App.jsx with a smaller component:

import './App.css' function App() { return ( <div className="App"> <h1>React notes</h1> <p>This page is rendered by a component.</p> </div> ) } export default App

Read the component

  • import './App.css' includes styles used by this part of the interface.
  • function App() declares the component. Component names must begin with a capital letter so React can distinguish them from HTML tags such as div.
  • return (...) describes the interface for this render. React compares later renders and updates only the DOM that changed.
  • export default App lets another file import this component with import App from './App.jsx'.
JSX resembles HTML, but it follows JavaScript rules. Use className instead of class, close every tag, and return one parent element or fragment.

JSX can include JavaScript expressions inside curly braces. For example, <p>{2 + 2}</p> renders the number 4. Statements such as if cannot be placed directly inside JSX, but their results can be stored in variables first.

Components

8

Create a component

What is a component?

A component is a JavaScript function that owns a piece of the interface. It can contain markup, styling hooks, event handlers, and state. A component may be as small as a button or as large as a complete page.

Components are composed rather than copied. A page component might render Header, Sidebar, and Article; Article might then render several smaller components.

Why not keep the whole page in App?

  • Readability: a name such as <UserProfile /> explains the purpose of a section without exposing all of its markup.
  • Reuse: one component can render in several places with different data.
  • Isolation: related markup and behavior stay together, so a change has a smaller area to affect.
  • Independent state: separate instances can remember separate values.
  • Testing: focused pieces are easier to test than one large page component.

Do not split every HTML element into its own component. Extract a component when a section has a clear responsibility, repeats, has its own behavior, or makes its parent difficult to read.

Declare and export Welcome

Create a new file src/Welcome.jsx:

function Welcome() { return ( <div> <h2>Welcome component</h2> <p>Components split an interface into reusable parts.</p> </div> ) } export default Welcome

The export makes Welcome available to other modules. Import it and render it in App.jsx:

import './App.css' import Welcome from './Welcome' function App() { return ( <div className="App"> <h1>React notes</h1> <Welcome /> <Welcome /> </div> ) } export default App
A component can appear more than once. Each <Welcome /> is a separate instance, even though both instances currently render the same markup.

Props and state

9

Pass data with props

Reusable components often need different content. Props, short for properties, are the inputs a parent component passes to a child component. They work much like function arguments.

  • Data flows down the component tree: the parent chooses the values and the child reads them.
  • Props are read-only. A child must not change the props it receives.
  • Text can use quotes, as in name="Alice". Numbers, variables, objects, and functions use curly braces, as in age={25}.
  • A prop can contain any JavaScript value, including another React element.

Read props in the child

Update Welcome.jsx:

function Welcome(props) { return ( <div> <h2>Hello, {props.name}!</h2> <p>You are {props.age} years old.</p> </div> ) } export default Welcome

React passes one props object to the function. The example reads props.name and props.age. Current React documentation often destructures these values in the parameter: function Welcome({ name, age }). Both forms are valid.

Supply props from the parent

Pass different values from App.jsx:

import './App.css' import Welcome from './Welcome' function App() { return ( <div className="App"> <h1>React notes</h1> <Welcome name="Alice" age={25} /> <Welcome name="Bob" age={30} /> </div> ) } export default App

Both instances use the same component definition, but the props produce different output. If the parent renders again with new values, React passes the new props to the child and updates the screen.

10

Update state with useState

State is a component's memory. It stores information that can change because of user input, a response from a server, or another event. When state changes, React renders the component again so the screen reflects the new value.

Why a normal variable is not enough

A local variable is created again each time the component function runs, and changing it does not ask React to update the screen. useState keeps a value between renders and provides a setter that schedules the next render.

How useState works

useState(0) returns a two-item array:

  • count is the state value for the current render. Its initial value is 0.
  • setCount requests a render with a new value.

The names are a convention created through array destructuring. Hooks such as useState must be called at the top level of a component, not inside a loop, condition, or nested function.

Build a counter

Create src/Counter.jsx:

import { useState } from 'react' function Counter() { // useState returns [currentValue, functionToUpdateValue] const [count, setCount] = useState(0) return ( <div> <h3>Counter: {count}</h3> <button onClick={() => setCount(current => current + 1)}> Increment </button> <button onClick={() => setCount(current => current - 1)}> Decrement </button> <button onClick={() => setCount(0)}> Reset </button> </div> ) } export default Counter

Each onClick receives a function. React calls that function after the user clicks; it must not be called while rendering. The increment and decrement buttons use an updater function because their next value depends on the previous value.

Calling a setter does not change the current count variable immediately. It queues another render. React then calls Counter again with the updated value.

Store only information the interface needs to remember. Values that can be calculated from existing props or state usually should be calculated during rendering instead of stored as more state.

Add the Counter to your App.jsx:

import './App.css' import Welcome from './Welcome' import Counter from './Counter' function App() { return ( <div className="App"> <h1>React notes</h1> <Welcome name="Alice" age={25} /> <Counter /> </div> ) } export default App

If <Counter /> is rendered twice, each instance receives its own independent count state.

Events and forms

11

Create a controlled form

React handles browser events through props such as onClick, onChange, and onSubmit. Pass a function to an event prop; React calls it when the event occurs.

What makes an input controlled?

A controlled input gets its displayed value from React state:

  • value={name} makes name the source of truth for the input.
  • onChange runs after the user types and copies e.target.value into state.
  • The state update renders the component again, and the input displays the new state.

This creates a loop: user input produces an event, the event updates state, and state updates the interface. Controlled inputs make validation, formatting, and conditional buttons easier because the current value is already available to the component.

Build the form

Create src/NameForm.jsx:

import { useState } from 'react' function NameForm() { const [name, setName] = useState('') const [submittedName, setSubmittedName] = useState('') const handleSubmit = (e) => { e.preventDefault() // Prevent page refresh setSubmittedName(name) } return ( <div> <form onSubmit={handleSubmit}> <label> Enter your name: <input type="text" value={name} onChange={(e) => setName(e.target.value)} placeholder="Your name here..." /> </label> <button type="submit">Submit</button> </form> {submittedName && ( <p>Hello, {submittedName}! Nice to meet you.</p> )} </div> ) } export default NameForm

Follow the submit flow

  • name tracks what is currently in the input.
  • submittedName stores the last value that was submitted. Keeping these values separate means the greeting does not change with every keystroke.
  • e.preventDefault() stops the browser's default form submission, which would navigate or reload the page.
  • setSubmittedName(name) saves the current input and schedules a render.
  • submittedName && (...) conditionally renders the greeting only when the string is not empty.
Keep the semantic form, label, and submit button. They provide keyboard behavior and accessibility that a collection of generic div elements would not.

Add it to your App:

import './App.css' import Welcome from './Welcome' import Counter from './Counter' import NameForm from './NameForm' function App() { return ( <div className="App"> <h1>React notes</h1> <Welcome name="Alice" age={25} /> <Counter /> <NameForm /> </div> ) } export default App
12

Combine the ideas in a todo list

The todo list combines the ideas above in one small feature: a controlled input collects text, state stores a list, event handlers update that list, and JSX renders one item for each object.

Plan the state

  • inputValue is a string containing the text currently in the input.
  • todos is an array of objects. Each object has an id, text, and completed value.
  • The total and completed counts can be calculated from todos, so they do not need separate state.

Update arrays without mutation

State should be treated as read-only. Do not call push, splice, or directly assign a property on the existing array. Create a new array instead:

  • spread syntax creates a new array with one additional item;
  • map creates a new array with one changed item;
  • filter creates a new array without the deleted item.

Build TodoList

Create src/TodoList.jsx:

import { useState } from 'react' function TodoList() { const [todos, setTodos] = useState([]) const [inputValue, setInputValue] = useState('') const addTodo = (e) => { e.preventDefault() if (inputValue.trim() !== '') { setTodos(currentTodos => [ ...currentTodos, { id: Date.now(), text: inputValue, completed: false }, ]) setInputValue('') } } const toggleTodo = (id) => { setTodos(currentTodos => currentTodos.map(todo => todo.id === id ? { ...todo, completed: !todo.completed } : todo )) } const deleteTodo = (id) => { setTodos(currentTodos => currentTodos.filter(todo => todo.id !== id)) } return ( <div> <h3>My Todo List</h3> <form onSubmit={addTodo}> <input type="text" value={inputValue} onChange={(e) => setInputValue(e.target.value)} placeholder="Add a new todo..." /> <button type="submit">Add</button> </form> <ul> {todos.map(todo => ( <li key={todo.id}> <button type="button" aria-pressed={todo.completed} onClick={() => toggleTodo(todo.id)} style={{ textDecoration: todo.completed ? 'line-through' : 'none' }} > {todo.text} </button> <button type="button" onClick={() => deleteTodo(todo.id)}>Delete</button> </li> ))} </ul> <p>Total todos: {todos.length} | Completed: {todos.filter(t => t.completed).length}</p> </div> ) } export default TodoList

Read the rendering logic

  • todos.map(...) converts each todo object into an li element.
  • key={todo.id} gives React a stable identity for each item. Keys help React track insertions, deletions, and reordering; they are not passed to the component as a normal prop.
  • The conditional textDecoration derives styling from todo.completed.
  • The toggle button uses aria-pressed so assistive technology can read its current state.
  • todos.filter(...).length derives the completed count during rendering.

The updater form of setTodos receives the latest array. This is the safest form when the next state depends on the previous state.

Date.now() is sufficient for this local exercise. Data from an API or database should use the stable identifier supplied by that data source.

Add the TodoList to your App:

import './App.css' import Welcome from './Welcome' import Counter from './Counter' import NameForm from './NameForm' import TodoList from './TodoList' function App() { return ( <div className="App"> <h1>React notes</h1> <Welcome name="Alice" age={25} /> <Counter /> <NameForm /> <TodoList /> </div> ) } export default App

Where to go next

13

Build from here

The examples cover React's core client-side loop: data enters through props or state, JSX describes the interface, and events request state changes. The next topics solve problems that appear as an application grows.

  • useEffect: Synchronize a component with something outside React, such as a browser API, timer, or third-party widget. Do not use an Effect for values that can be calculated while rendering.
  • React Router 8: Map URLs to screens, create nested layouts, and load route data with React Router.
  • Context: Make a value available to a distant part of the component tree without passing it through every intermediate component.
  • Custom Hooks: Move reusable stateful logic into a function whose name begins with use. Hooks reuse behavior, not rendered markup.
  • Testing: Use Vitest with React Testing Library. Prefer tests that interact with the interface the way a user would.
  • Production build: Run npm run build. Vite bundles the application into dist/, which services such as Vercel and Netlify can host. Run the linter separately before deployment.
  • React Compiler: Try it later with Vite's react-compiler template. It can optimize component rendering, but it is deliberately not enabled in the basic template.
